# 10 реалистичных запросов — 22.10.2026

Проверка через HTTP → классификатор → реальный stdio MCP → нормативные файлы → рабочую модель. Модель и классификатор: `deepseek-v4.1-flash`, Tooken Club. Синтетические бытовые запросы; начальная анкета от пустой до подробной, включая неизвестные сведения и исправление членства в истории. Реальные клиентские персональные данные не использовались.

Входные случаи: [legal-realistic-10.json](../examples/legal-realistic-10.json). Исходные ответы, планы, прочитанные фрагменты и диагностика сохранены локально в игнорируемом каталоге `data/realistic-10-2026-10-22/`; секретов в отчёте нет. Первичный прогон не перезаписывается повторными проверками.

## Что произошло в неудачных случаях

### 4. Забор соседа — промах поиска, а не недостаток вводных

Классификатор понял задачу правильно. Но поиск вернул статью о некапитальных гаражах, положения о проекте межевания сельхоздоли и публичных слушаниях. Модель обоснованно отказалась строить совет на этих материалах. Заполнение кадастрового номера само по себе этот дефект не исправляет.

В имеющейся базе есть нормы о восстановлении нарушенного земельного права и земельных спорах. Проверочный поиск по их смысловым терминам находит их. Требуется раскрывать бытовые слова «сосед передвинул забор/занял часть земли» в юридические поисковые термины; не закреплять в коде ответ или единственный номер статьи. Индивидуальная граница и наличие нарушения остаются непроверенными.

### 8. HTTP 502 — провайдер не выдал даже план

Внутренний код llm_http, HTTP 502, этап classify. Нормативный поиск и подготовка ответа ещё не начинались. Подробность анкеты не является подтверждённой причиной 502. Внутренняя причина на стороне провайдера неизвестна. Для отличия временного сбоя от воспроизводимой ошибки выполняется отдельный явно учтённый повтор; скрытые платные повторы не добавляются.

### 9. Обрезанная классификация

Код llm_truncated на этапе classify. В адаптере плану выделено 768 выходных токенов; сообщение провайдера finish_reason=length отклоняется, частичный JSON в работу не поступает. После добавления known_fields план стал объёмнее, но бюджет остался прежним. Нельзя утверждать, какая доля лимита ушла на внутреннее рассуждение: текущая диагностика этого не фиксирует. Требуется увеличить ограниченный бюджет классификации и проверить исходный сценарий. Увеличение сетевого таймаута не устраняет обрыв по max_tokens.

### 10. Корректировка членства понята, но проверка оснований слишком узкая

Классификатор учёл последнее сообщение: собственник не является членом СНТ. Ошибка памяти в этом примере не обнаружена. Он выделил две задачи — документы и платежи.

В пояснении к прочитанному фрагменту статьи 17 модель сослалась на статью 5, также прочитанную и выбранную в основаниях. Проверка пояснения сопоставляет реквизиты только с одним собственным фрагментом, поэтому отклонила эту межстатейную ссылку. Дополнительно основной текст ссылался на статью 11, не раскрытую в выбранном контексте: эта часть требует ограниченной правки изложения, а не снятия проверки. Сейчас код invalid_legal_bases не допускает уже имеющийся единственный проход исправления реквизитов.

Нужны отдельные проверки структуры/ID и реквизитов: ссылки допустимы в пределах реально прочитанных выбранных оснований; неизвестные реквизиты по-прежнему блокируются. Только ошибка изложения может отправляться на один ограниченный проход исправления. Вымышленные ID не исправляются автоматически и не принимаются за результат.

## Пробел покрытия и качества интерфейса

Вопрос 7 не следует превращать в догадки о сроках наследования. Для него требуются дополнительные нормативные материалы с отдельной проверкой. Общая фраза текущего отказа «уточните ситуацию» плохо объясняет проблему: нехватка норм не устраняется дополнительными полями клиента. Желательно явно различать отсутствие нормативных оснований и отсутствие фактов.

В успешных ответах также заметны повторения одного и того же названия закона/статьи для нескольких пояснений. Это не технический сбой, но ухудшает краткость. Отдельная будущая доработка — группировка оснований по акту и статье без потери значимых пояснений.

## Брейншторм: варианты

1. Увеличить контекст и лимиты всех вызовов, отключить строгую проверку. Не выбран: это увеличит расход и позволит неподтверждённые ссылки, не решив промах поиска.
2. Добавить ручные готовые ответы на все эти случаи. Не выбран: плохо переносится на другие формулировки и не устраняет общие причины.
3. **Выбранный точечный путь:** улучшить смысловое расширение поиска по земельным спорам; увеличить ограниченный бюджет только классификатора; сверять реквизиты пояснений с набором выбранных прочитанных оснований; сохранять единственный проход исправления только для ошибок изложения. HTTP 502 перепроверять отдельно, не объявлять провайдера исправленным. Пробел наследственного покрытия описать явно.

Это изменения существующей цепочки, без новых подсистем. Подтверждение точечного исправления запрошено через асинхронный вопрос по правилу brainstorming; до подтверждения продуктовый код не менялся. После согласования нужны регрессионные тесты, адресный повтор случаев 4, 9, 10 и контроль соседних успешно пройденных сценариев. Повтор случая 8 должен учитываться отдельно от изменения кода и от исходных 10 запросов.

## Дополнительные диагностические пробы — исходный прогон сохранён

- Случай 8 повторён отдельно **без изменения кода и данных**: partial_answer, 27,74 с. Ответ раскрыл денежную сторону защиты и прямо ограничил выводы по сохранению участка/обжалованию. Это подтверждает, что конкретный HTTP 502 был временным; первичный сбой не исключается из статистики и доступность провайдера не объявляется исправленной.
- Для случая 9 выполнен отдельный вызов только классификатора с max_tokens=2048 вместо 768, без правки продуктового адаптера. Получен полный план за 8,35 с, finish_reason=stop. Провайдер сообщил completion_tokens=834, в том числе reasoning_tokens=633. Эта проба показывает, что рабочему плану может требоваться больше прежнего лимита 768. Полный пользовательский ответ по продаже этим вызовом не проверялся.
- После отдельного повтора случая 8 по всем уникальным сценариям есть 6 полезных результатов, 3 остающихся провала и 1 корректный отказ по отсутствующему покрытию. Это сводка с адресным повтором, **не повторный полный прогон 10/10**.
- Поиск и валидация пока не менялись: для внесения согласованного исправления требуется ответ на вопрос brainstorming. Уточнённый дизайн включает три причины: смысловое расширение поиска земельных споров; бюджет классификатора 2048; сопоставление реквизитов с набором выбранных прочитанных оснований и один ограниченный проход исправления только ошибок изложения.

## Внесённые исправления и итог повторов

Пользователь подтвердил доработку. Выполнены четыре точечных изменения:

1. Для бытового спора о соседском заборе поиск расширяет запрос терминами восстановления нарушенного права, самовольного занятия и земельного спора. Номера статей и готовый правовой вывод в код не зашиты.
2. Бюджет классификатора увеличен с 768 до 2048 токенов. Сетевые таймауты не увеличивались; обрезанный JSON по-прежнему отвергается.
3. Реквизиты пояснений проверяются по набору выбранных реально прочитанных оснований. Структура и ID проверяются отдельно. Только непроверенное упоминание реквизитов допускает уже существующий единственный проход исправления; поддельные ID не допускаются.

Реальные реестровые сведения и документы клиента не проверялись. Проверка структуры, прочитанных ID и реквизитов не является независимой юридической экспертизой каждого вывода.

В скрипте `scripts/evaluate_legal.py` также устранены устаревшие условия проверки: он передаёт историю, принимает несколько ожидаемых статусов и допускает подтверждённые правовые основания. Ранее он ошибочно считал бы любой номер статьи провалом. Пример воспроизведения набора:

```bash
.venv/bin/python scripts/evaluate_legal.py --live \
  --cases examples/legal-realistic-10.json \
  --output data/realistic-10-next-run
```

Автоматическая оценка статуса требует ручной проверки полезности и применимости, как и в первоначальном прогоне. Содержимое вопроса и анкеты в повторных случаях не улучшалось искусственно.
