# Память чата и правовые основания — 22.10.2026

По подтверждённому требованию пользователя отменено прежнее скрытие правовых оснований. Теперь рядом с ответом показываются название акта, статья и очень короткое объяснение её значения. Внутренние ID, хеши, трассировка и реквизиты API по-прежнему не публикуются.

## Память

В IndexedDB браузера сохраняются сообщения и переданные анкеты. При новом вопросе в API передаются предыдущие сообщения клиента из текущего чата с их анкетами. При уточнении старого вопроса используется история только до этого вопроса. Исходный текст остаётся отдельным полем; ответы модели не превращаются в факты клиента. MCP полную историю не получает.

Историю получают классификатор и исполнитель. Классификатор возвращает known_fields — известные сведения для текущего объекта; сервер проверяет допустимые ключи и размеры значений. Текущая анкета имеет приоритет. Поля с уже известными значениями, включая «не знаю», повторно не предлагаются. В инструкции запрещён перенос фактов на другой объект; если привязка неясна, требуется уточнение. Смысловое выделение фактов выполняет модель, поэтому оно не является подтверждением реестровых сведений.

Данные разных чатов не объединяются. Сервер не хранит общую память пользователей. Перезагрузка страницы сохраняет память; очистка данных сайта, другой браузер или устройство её не переносят. Вложенные файлы не анализируются. Лимит истории — 200 сообщений клиента и 100 000 символов суммарного текста с анкетами; превышение возвращает понятную ошибку без скрытого обрезания истории. HTTP-тело ограничено 256 КиБ.

## Правовые основания

Модель возвращает legal_bases: ID прочитанного фрагмента и пояснение до 400 символов. Сервер проверяет ID и формат, затем подставляет название акта и статью из файловой базы. Номер и дата федерального закона извлекаются из заголовочных реквизитов проверенного файла; модель их не сочиняет. Клиент получает только title, article, explanation. Для рабочего содержательного ответа наличие оснований обязательно; при недостатке материалов сохраняется insufficient_sources.

Основной текст и условные варианты описывают действия простыми словами. Реквизиты отображаются в отдельном блоке «Правовые основания»; краткие упоминания тех же прочитанных актов и статей допускаются и в тексте. Старый безусловный запрет реквизитов заменён проверкой их наличия в выбранных основаниях. Непрочитанные статьи и акты, URL и внутренние ID не допускаются. Наличие ID подтверждает происхождение фрагмента, но не доказывает юридическую правильность свободного объяснения. Сохраняются ограничения неполных данных и частичного покрытия нормы.

При проверке продолжения вопроса про СНТ выявлен выбор смежной статьи: поиск теперь раскрывает сокращение СНТ в «товарищество», чтобы находить нормы о правах члена, а не о членах иных организаций.

## Проверки

Добавлены проверки передачи истории обеим моделям, подавления уже известных полей, некорректной истории, неизвестного ID основания, отсутствия общей серверной памяти и поиска по сокращению СНТ. JS-проверки охватывают границы истории и сохранение публичных правовых оснований. Браузерный прогон с контролируемыми API-ответами проверяет уточнение, следующий вопрос, перезагрузку, новый чат и отсутствие ошибок JS: `tests/browser_memory.py`.

## Сохранение ответа при ошибке обновления

При уточнении уже отвеченного вопроса предыдущий успешный ответ остаётся видимым вместе с правовыми основаниями. Состояние обновления сохраняется в IndexedDB. При HTTP/модельной ошибке, некорректном запросе, отсутствии материалов или отмене обновления сохраняется старая версия с явной отметкой: новые уточнения в ней не учтены. Можно повторить запрос. Несколько ошибок подряд не стирают успешный ответ; успешный новый результат заменяет его и убирает отметку. Перезагрузка во время обновления восстанавливает прежний ответ с предупреждением после подключения интерфейса. Для первого запроса, когда успешного ответа ещё нет, показывается ошибка; ответ другого вопроса не используется.

Проверки: `tests/web_legal.test.cjs`, `tests/browser_answer_fallback.py`.
