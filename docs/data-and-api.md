# Данные и API

## Хранилище

SQLite в `DATA_DIR/assistant.sqlite3`, WAL, внешние ключи. Оригиналы мониторинга — `DATA_DIR/sources/`. Загруженные результаты НСПД — `DATA_DIR/nspd_reports/`; записи `nspd_reports` связаны с делом, содержат хеш, время получения и непроверенные метаданные. Вложения доступны в Telegram и ZIP документов; отдельные HTTP-маршруты вложений пока не добавлены. Анализы сохраняются отдельно и содержат ссылки на конкретные версии правил. Журнал `audit` фиксирует действия без копирования персональных данных. Дела доступны Telegram-пользователю только по его ID; закрытый API предназначен для администратора и имеет доступ ко всем делам.

У приложения нет полноценной модели ролей, удаления/сроков хранения, шифрования БД и управления согласиями. Перед вводом персональных данных в промышленную эксплуатацию эти процессы нужно согласовать и реализовать. Резервировать базу следует средствами SQLite backup либо при остановленных процессах; простое копирование одного файла при активном WAL недостаточно.

## Импорт муниципалитета

`id`, `name`; опционально `boundary` — простой полигон WGS84 `[долгота,широта]`, `source_url`, `verified_at` (YYYY-MM-DD). Для границы источник и дата обязательны. Дыры и мультиполигоны пока не поддерживаются; их нельзя упрощать без проверки влияния на границы. Если весь участок не покрыт единственной границей, автоматическое определение не подтверждается. `examples/municipality.demo.json` — только форма данных.

## Импорт ПЗЗ

См. `examples/rule.demo.json`. Обязательны муниципалитет, зона, версия, источник, цитируемый пункт, `effective_from`, `valid_until`, основные разрешённые ВРИ и числовые ограничения. Отсутствие применимого ограничения задаётся `null` и приводит к запросу уточнения, а не подменяется нулём. `verified_by` активирует редакцию; без этого поля запись сохраняется как непроверенная. Импортировать в рабочую базу может только доверенный администратор. Подтверждение не является криптографической подписью.

`valid_until` — крайняя дата подтверждённой актуальности, установленная специалистом, а не предположение о юридическом сроке действия акта. Все даты для проверки актуальности используют часовой пояс Europe/Moscow. Замена активной редакции производится атомарно; история сохраняется.

Ограничения применяются ко всей зоне, а не к отдельным ВРИ. При наличии разных требований для разных ВРИ/подзон схема должна быть расширена до заполнения реальными ПЗЗ. Нельзя сводить неоднозначные нормы к единому числу без проверки.

## Карточка участка

См. `examples/case.json`. Обязательны `client`, `address`, `purpose` (`housing`, `commercial`, `agriculture`). Для образуемого участка `cadastre` можно не задавать. Координаты — только WGS84, не МСК и не Web Mercator.

Для подробной предварительной проверки нужны площадь из документа, ВРИ, зона с источником и проверяющим, категория, права, параметры проекта, подтверждённая проверка ограничений и документ-основание. `setback_m` — минимальный фактический отступ по исходным данным проекта. `floor_area_m2` — суммарная площадь этажей для загруженного коэффициента; используемое определение плотности необходимо проверить по конкретным ПЗЗ. Проверка геометрической площади допускает расхождение до 5% исключительно как предварительный индикатор.

`utilities` — объект с подтверждёнными данными сетей для image adapter; ядро пока не проверяет геометрию этих данных и не определяет техническую возможность подключения.

## Нормативная выдержка

```json
{
  "kind": "land_code",
  "title": "Название акта",
  "version": "Редакция, установленная специалистом",
  "source_url": "https://official.example/document",
  "citation": "Статья и пункт",
  "content": "Текст проверенной выдержки",
  "valid_until": "2026-10-31",
  "verified_by": "Ответственный юрист"
}
```

Пример структуры, не реальный нормативный акт. Поддерживаются `land_code`, `town_code`, `civil_procedure`, `101-fz`, `217-fz`. Поиск возвращает совпавшие проверенные выдержки; морфологический поиск, семантические embeddings и исчерпывающий правовой поиск не реализованы.

## Источник мониторинга

```json
{
  "title": "Официальная публикация ПЗЗ",
  "url": "https://official.example/document",
  "municipality_id": "simferopol-city",
  "kind": "pzz"
}
```

URL-пример не рабочий источник. `kind` — `pzz` или один из пяти видов актов выше. Для общих актов `municipality_id` опускается. Первая загрузка — базовая версия без оповещения; последующие отличия нормализованного текста — уведомления. Для HTML учитываются адреса ссылок, но автоматически переходить по ним и интерпретировать поправки программа не умеет. Каждый юридически значимый документ нужно зарегистрировать отдельно. Ошибки извлечения видны в `sources.error` и не стирают базовую версию.

Оповещения всем делам в муниципалитете намеренно широкие: изменение может затрагивать зону, даже если номер дела в тексте отсутствует. Прямое совпадение кадастрового номера/адреса помечается отдельно. Семантическая применимость поправки автоматически не устанавливается.

## HTTP API

Запуск: `python -m land_assistant api`. По умолчанию `127.0.0.1:8080`. Все маршруты, включая health, требуют `Authorization: Bearer <ADMIN_API_TOKEN>`. Токен — минимум 32 символа. CORS не включён. Внешний доступ — через TLS reverse proxy с ограничением сети, частоты запросов и времени чтения.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Состояние процесса |
| GET/POST | `/municipalities` | Список/импорт муниципалитетов |
| GET/POST | `/rules` | Список/импорт ПЗЗ |
| GET/POST | `/sources` | Список/регистрация источников |
| POST | `/legal-documents` | Импорт нормативной выдержки |
| POST | `/legal-search` | `{kind, query}` — поиск по выдержкам |
| GET/POST | `/cases` | Список/создание; в POST дополнительно `owner_id` |
| GET/POST | `/cases/ID` | Карточка/частичное обновление |
| POST | `/cases/ID/analyze` | Новый сохранённый анализ; тело `{}` |
| GET | `/cases/ID/documents` | ZIP документов с новым анализом |
| GET | `/notifications` | Очередь и история уведомлений |
| POST | `/monitor` | Проверка всех зарегистрированных источников; тело `{}` |

POST — JSON-объект до 1 МБ. Ошибки: 400 — входные данные/конфликт импорта, 401 — авторизация, 404 — маршрут, 500 — внутренняя ошибка. Локальный CLI имеет административный доступ к базе и должен запускаться только доверенным пользователем ОС.
