# Legal Help Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Рабочий локальный веб-прототип согласованной цепочки с настоящим файловым MCP и явно разделёнными demo/live.

**Architecture:** Python-хост валидирует ввод и план, собирает контекст через отдельный MCP `legal_help`, получает ответ и внутренне проверяет происхождение контекста. Клиенту источники не показываются. Веб-интерфейс groundAndLaw сохраняется и обращается к узкому API; .txt/.md доступны только MCP.

**Tech Stack:** Python 3.11+, официальный MCP Python SDK 1.x с зафиксированной версией, stdlib HTTP/SQLite-independent search; существующие HTML/CSS/JS и IndexedDB.

**Spec:** docs/superpowers/specs/2026-10-20-local-legal-mcp-design.md, включая уточнения 21.10.2026.

## Global Constraints

- Только локальные файлы MCP; НСПД/ЕСИА отложены.
- По доработке 21.10.2026 источники нигде не отображаются клиенту; контекст и его идентификаторы остаются внутри сервера. Изменение кода запланировано в Task 5.
- Одна функция — один MCP; активна только legal_help.
- Вопрос до 8000 символов; JSON до 64 КиБ; до 4 задач, 6 фрагментов и 16000 символов контекста.
- Demo явно учебный и без LLM; live без настроенной модели не стартует.
- Существующие изменения не коммитить и не перезаписывать; .env не публиковать.

## Review Focus

- Пустой/огромный/неполный запрос не вызывает MCP или платную LLM до нужной проверки.
- Переключение/удаление чата во время ответа не переносит ответ в чужой чат.
- Неизвестные ID источников и фразы-инструкции из документов не становятся подтверждёнными основаниями.
- Отсутствующий/изменённый файл и symlink не читают секреты и не используют старый контекст молча.
- Таймаут/ошибка MCP/LLM отражается как ошибка, без повторного платного вызова и имитации успеха.
