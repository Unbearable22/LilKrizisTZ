# Юридические ответы с поиском проверенных источников

Дата: 2 ноября 2026 года. Статус: согласованная подсистема реализована и проверяется живыми запросами. Поиск не требует внешнего поискового провайдера; полный цикл зависит от времени работы LLM. Актуальные результаты и ограничения приведены в [отчёте](../../verified-source-evaluation-2026-11-02.md).

## Цель и границы

На юридический вопрос по праву РФ пользователь получает взвешенный ответ: подтверждённую часть, условные варианты, следующие шаги, недостающие сведения и проверяемые ссылки на использованные документы. Это распространяется на все поддерживаемые юридические темы, а не только на продажу недвижимости. Несколько задач одного сообщения обрабатываются раздельно с общим контекстом фактов и бюджетом.

«Любой запрос» означает осмысленную реакцию на каждый запрос, но не обещание найти действующее основание и дать окончательный юридический вывод по любому вопросу. Неюридические вопросы и право других стран остаются вне текущего профиля. Нельзя выдумывать правила, суммы, сроки или ссылки, если доказательств нет. Неизвестные клиенту сведения не становятся обязательной полной анкетой: при достаточных нормах даются варианты «если». Регистрация действий, отправка заявлений, НСПД/ЕСИА и серверное размещение сюда не входят.

Новое требование пользователя отменяет прежнее скрытие ссылок. При этом личные данные, внутренние журналы и сырые идентификаторы файлов не публикуются.

## Текущее состояние и проблема

Существуют локальный земельный MCP, публичный MCP КонсультантПлюс, отдельный резервный проход для продажи недвижимости и страница ФНС. Система проверяет форматы и известные ID, но это не проверка смысловой обоснованности всех выводов. Веб-чат показывает названия актов без ссылок. История сохраняется в IndexedDB и изолирована по чатам.

Прогон пяти тем 02.11.2026: 3 предварительных ответа и 2 отказа. Земельные документы исключены из-за истечения valid_until=22.10.2026; потребительский вопрос получил только статью о сроках. Механическое продление valid_until недопустимо. При поиске необходима загрузка недостающих релевантных норм, а не повтор тех же материалов.

## Выбранная схема

Сообщение и история → классификация задач → проверка доступного локального/нормативного контекста → определение пробелов → поиск через MCP по доверенным ресурсам → загрузка и проверка документов → подбор фрагментов → структурированный ответ → проверка связи выводов с доказательствами → ответ и кликабельные источники.

Поиск вызывается при недостатке или истечении срока проверки материалов любой поддерживаемой темы. Ограничение текущего резервного прохода только продажей недвижимости снимается. Достаточный проверенный локальный контекст не требует сетевого поиска без причины. Результаты поиска и сниппеты используются только для обнаружения страниц; источником ответа становится реально прочитанный документ.

Приложение-хост управляет задачами и бюджетом. Бизнес-функции legal_help и general_legal_help сохраняют собственные MCP. Общие поисковые/сетевые компоненты подключаются к их серверным инструментам как библиотека; нет нового бизнес-маршрута «ответить по Интернету». Это сохраняет решение «для каждой функции свой MCP».

## Поиск без платных провайдеров

Новое ограничение пользователя: использовать бесплатные решения для поиска. Brave Search API исключён из предлагаемой схемы; отдельные платные подписки, SEARCH_API_KEY и закупка поисковых запросов не требуются. Сама генерация через уже выбранный Tooken Club остаётся отдельным расходом; замена LLM на локальную модель не согласована.

Согласованный подход: поиск непосредственно внутри разрешённых источников плюс локальный индекс прочитанных документов. Используются существующие каталоги актов/оглавления, общедоступный поиск конкретного сайта там, где его формат и условия допускают автоматическое использование, и опубликованные карты сайта/ссылки. Не предполагается, что у каждого ведомства есть бесплатный API: доступность способа обнаружения и извлечения подтверждается отдельно для каждого адаптера.

SQLite-индекс хранит названия, типы, реквизиты, темы и фрагменты с доказанным происхождением. Он наполняется автоматически разрешённым ограниченным обходом, а не составляется только вручную. Во время вопроса выполняется поиск по индексу и адресное обнаружение/обновление документов. Начальная индексация и обновления отделены от 120-секундной обработки сообщения: обход всего сайта ради одного вопроса недопустим. Индекс, кеш и журнал ограничены по размеру; источники не помечаются свежими без подтверждения.

Это специализированный поиск по доверенным юридическим ресурсам, а не полный глобальный веб-индекс. Охват и устойчивость зависят от открытости сайтов. CAPTCHA, запреты, недоступные документы и неизвестная разметка не обходятся; используются другие разрешённые источники или объясняется ограничение. Нельзя обещать содержание по любому вопросу только потому, что поиск не требует подписки.

SearXNG — возможная бесплатная по лицензии альтернатива: он агрегирует сторонние поисковые системы, но требует отдельного развёртывания и зависит от доступности этих систем. В первый вариант не включается, чтобы не добавлять отдельный сервис к Windows-запуску и не делать публичные нестабильные экземпляры обязательной зависимостью. Документация: https://docs.searxng.org/.

Служебные результаты обнаружения не считаются доказательствами. Нормативный вывод строится только по успешно загруженному и проверенному материалу. Оплата обычного Интернета, компьютера/будущего хостинга и действующей LLM не объявляется нулевой стоимостью эксплуатации.

## Источники и приоритет

В версионируемом реестре хранятся домены, тип источника, допустимые пути, юрисдикция, тема и правила извлечения. Официальный домен сам по себе ещё не подтверждает применимость конкретного материала.

Начальные категории:

- publication.pravo.gov.ru и pravo.gov.ru — официально опубликованные акты; отдельная публикация поправки не объявляется полным консолидированным текстом закона.
- consultant.ru и garant.ru — проверяемые тексты норм, с сохранением согласованного приоритета КонсультантПлюс при сопоставимых редакциях/датах.
- nalog.gov.ru, rosreestr.gov.ru, rostrud.gov.ru, rospotrebnadzor.ru, sfr.gov.ru, cbr.ru — документы и разъяснения соответствующих ведомств.
- vsrf.ru и явно разрешённые судебные домены — документы судов; решение по конкретному делу не становится универсальной нормой.

Перечень — план подключения, а не подтверждение готовности всех адаптеров. Сайты общего назначения, форумы, блоги, реклама, ответы нейросетей, зеркала и похожие домены не включаются. Поддомены разрешаются только политикой конкретного ведомства; общего правила «любой *.gov.ru» нет.

Противоречия сравниваются с учётом юридической силы, даты действия и территории. Разъяснение не отменяет норму, а приоритет Консультанта не означает, что он может отменить официальный акт. Если нельзя определить применимую редакцию, спорный вывод не делается, расхождение обозначается явно.

## Проверка и извлечение

Для документа устанавливаются: фактический URL, издатель, тип, заголовок, номер/дата акта при наличии, дата публикации/редакции/вступления в силу, юрисдикция, дата загрузки и хеш текста. Эти даты не взаимозаменяемы. Текущая дата в футере сайта не доказывает действие нормы.

Известные HTML-форматы извлекаются отдельными адаптерами. Текстовые PDF допускаются после ограниченной загрузки и извлечения с привязкой к странице. PDF-сканы и неизвестная разметка получают source_unreadable; OCR не входит в первую реализацию. CAPTCHA, авторизация, проекты, рекламные обзоры и архивные редакции не превращаются в действующие нормы. Условия применимости и исключения не отрезаются незаметно; при неполном контексте это обозначается.

Исторический запрос обслуживается только доказанной редакцией на нужную дату. Если доказана подлинность документа, но не актуальность/применимость, его статус не повышается до «действующая норма» автоматически. Реестр, права на участок и фактические обстоятельства клиента не считаются проверенными поиском.

## Ответ и доказательства

Модель готовит ответ. Хост подбирает дословные текстовые опоры для полных разделов ответа и условных вариантов из прочитанных фрагментов. Отдельный обязательный модельный проход проверяет их смысловую обоснованность; механическое совпадение слов не означает подтверждения. Разделение принято после измерения задержек совмещённой генерации ответа и цитат. Модель проверки настраивается отдельно через LLM_VERIFIER_MODEL, без отдельного ключа. У каждого вывода есть уровень: подтверждённый общий порядок, условный вывод или неподтверждённая часть. Не используется вымышленный процент уверенности.

Детерминированная проверка подтверждает существование ID, совпадение цитируемого текста, допустимость реквизитов, ссылки и статуса документа. Дополнительный ограниченный LLM-проход проверяет смысловую связь вывода с переданными материалами; это вспомогательная проверка, а не доказательство юридической достоверности. Необоснованные части удаляются или заменяются явным ограничением. Допускается один проход исправления; бесконечных повторов нет. Можно сохранить неизменённые разделы, прямо одобренные проверяющей моделью, с явной отметкой неполноты; отрицательный ответ или таймаут не разрешают публиковать остальные разделы. Сбой проверки не превращает непроверенный черновик в успешный ответ.

Публичный формат содержит ответ, условные варианты, следующие шаги, недостающие сведения, ограничения и evidence. Для каждого evidence сервер формирует title, publisher, source_kind, url, citation, published_at/revision (если доказаны), checked_at и связь с выводами. URL берётся только из успешно загруженного разрешённого документа, не из генерации модели. В тексте допустимы ссылки [1], [2], раскрываемые сервером в документы; неизвестный номер отклоняется.

Интерфейс отличает закон, официальное разъяснение и судебный документ, показывает дату проверки и открывает ссылки безопасно. Источники сохраняются вместе с ответом в IndexedDB. Старые чаты без ссылок не получают вымышленные ссылки задним числом. При ошибке уточнения сохраняется прежний проверенный ответ с прежними основаниями/датой и отметкой неучтённых уточнений.

## Сеть, приватность и бюджеты

Поисковым интерфейсам разрешённых сайтов передаётся отдельная обезличенная юридическая формулировка и необходимая территория из закрытого каталога. Полный вопрос, история, ФИО, точные адреса, кадастровые номера, телефоны и номера личных документов не пересылаются. Одного обещания LLM «удалить персональные данные» недостаточно: параметры поиска ограничивает приложение. На сайты ведомств не отправляется текст вопроса.

Сетевой слой проверяет HTTPS, разрешённый хост/путь, отсутствие учётных данных, допустимый порт и каждый редирект; запрещает приватные/loopback/link-local IP и перепривязку DNS при соединении. Произвольные URL из вопроса не загружаются. Не обходятся 401/403/429, CAPTCHA и авторизация. Тексты страниц рассматриваются как данные, не инструкции.

Общий срок запроса остаётся 120 секунд. Внутри него резервируется время на поиск, ответ и проверку; не запускаются стадии, которым не осталось времени. Начальный предел: до 2 поисковых запросов, до 10 кандидатов из каждого, до 6 новых документов; общее чтение документов по всем задачам ограничено 8, включая текущие нормативные инструменты. Сохраняется общий лимит контекста 20 тысяч символов. HTML — до 2 МиБ, PDF — до 8 МиБ и 30 страниц. Изменение этих пределов требует явного решения по результатам измерений, а не скрытого увеличения таймаута.

Кеш и журнал изменений остаются вне Git с ограничениями срока/размера, устойчивыми ID и проверкой хеша. Запись без подтверждения свежести не получает новую дату проверки при сетевом сбое. Логи содержат run_id, этап, код ошибки, числовой usage и затраты времени, без ключей и переписки. Поисковые адаптеры не получают ключ LLM; отдельного платного поискового ключа в этой схеме нет.

## Критерии приёмки

1. Изъятие участка с истёкшей локальной проверкой вызывает поиск действующих материалов, а не продление valid_until без сверки.
2. Неисправный телефон без чека: поиск получает основания по правам при недостатках и доказательству покупки; одна статья о сроках не выдаётся за достаточный контекст всей ситуации.
3. Проверяются налоги, наследство после пропуска срока, труд, семья, жильё, потребительские и земельные вопросы с неполными вводными.
4. Все публичные ссылки соответствуют действительно прочитанным разрешённым документам; проверяются поддельный домен, редирект, локальный IP, непроверенный ID, вымышленная цитата и инструкция в тексте страницы.
5. Различаются ошибка поиска, ещё не наполненный индекс, недоступность источника, непрочитанный PDF, неизвестная редакция и нехватка оснований. Сохраняется подтверждённая часть смешанного запроса.
6. Пройдены модульные/stdio/браузерные тесты. Живой поиск проверяется на реальных открытых источниках; фикстуры не выдаются за такой прогон. Отчёт разделяет полезные ответы, ограниченные ответы, отказы и технические ошибки; не обещает ответ на любой юридический вопрос.
